# Frontend

One Vue bundle, **three runtime modes**, one shared `Backend` seam. The frontend
never owns the command contract — it imports the generated TypeScript contract
(`shared/generated/rpc-commands.ts`) and multiplexes reads/writes through a single
`Backend` interface over whichever transport is active.

## Tech

Vue 3 + TypeScript + Vuetify 3 + Vite + Pinia.

## Runtime modes

`src/services/runtime.ts` picks the mode; `src/services/backend/createBackend.ts`
builds the matching `Backend` once in `main.ts`:

| Mode | Detection | `Backend` impl |
|------|-----------|----------------|
| `desktop` | `isTauri` | `tauriBackend.ts` (Tauri `invoke` via `src/services/invoke.ts`) |
| `webHost` | not Tauri + `GET /session` returns a code | `webHostBackend.ts` (`fetch` against `/rpc` + media routes) |
| `guest` | not Tauri + `#code.token` in the hash | `guest.ts` + `peer.ts`/`protocol.ts` (WebRTC RPC) |

Authorization is **server-side**: `dispatch` decides based on `--share-mode` /
`--owner-mode`. The frontend has no ro/rw/owner branching.

## The backend seam

`src/services/backend/interface.ts` declares `Backend` (typed, command-name-level
methods). All three transport implementations satisfy it, so stores/views are
transport-agnostic.

- **Generated contract**: command names, tiers, arg names, and payload casing come
  from `shared/generated/rpc-commands.ts` (committed, drift-guarded in Rust).
- **Casing helper**: `src/services/backend/rpcCasing.ts` derives allowed command
  names and args from the same generated catalog and snake-cases payload keys —
  used by `guest.ts` and `webHostBackend.ts` so wire payloads always agree with
  the Rust `dispatch` (which is the source of truth).
- `invoke.ts` imports `STRINGIFY_RESULT` from the generated contract for Tauri
  stringified results.

## Directory structure

```
src/
├── services/
│   ├── backend/            # interface.ts + tauriBackend/webHostBackend/guest (+peer/protocol)
│   │   ├── createBackend.ts # mode → Backend (built once in main.ts)
│   │   ├── bootGuest.ts     # guest bootstrap from #code.token
│   │   ├── rpcCasing.ts     # contract-driven snake_casing
│   │   └── mediaRegistry.ts # media URL resolution across modes
│   ├── runtime.ts           # mode detection
│   ├── invoke.ts            # Tauri invoke layer (stringify via contract)
│   ├── events.ts, signalling.ts, tauri.ts, theme.ts
├── stores/             # Pinia stores (albums, app, mapFilter, models, runtime,
│                       #   scan, search, settings, sync, ui)
├── composables/        # useConnect, useSettings, usePeople, useLocale,
│                       #   useMediaUtils, useMediaUrl, useSwipeCarousel, …
├── components/         # 50+ Vue components (connect/, media/, settings/, sync/,
│                       #   models/, people/, scan/, common/)
├── types/, locales/    # types + 8 locale files (en canonical)
└── __tests__/          # unit tests incl. backend seam + casing tests
```

## State management (Pinia stores)

| Store | Purpose |
|-------|---------|
| `app` | initialization state, onboarding completion |
| `ui` | theme, sidebar, current view |
| `runtime` | runtime mode + active backend |
| `search` | query, results, filters, pagination |
| `sync` | sync progress, peers, status |
| `scan` | scan progress, file counts |
| `models` | model download/load status |
| `albums`, `settings`, `mapFilter` | albums, config, map filter |

## Composables

`useConnect` (host/join state machine, discovery, WebRTC events), `useSettings`,
`usePeople` (face/person CRUD), `useLocale`, `useMediaUtils`, `useMediaUrl`,
`useSwipeCarousel`, `useTimePeriods`, `useDoubleTap`.

## Events

Rust bridges to the UI through the transport (Tauri events on desktop;
`events.ts` abstracts the browser paths). Key events: `scan-progress`,
`indexing-progress`/`indexing-eta`, `sync-progress`, `webrtc-state`,
`peer-connected`/`peer-disconnected`, `room-code`, `photo-analysis-result`,
`photo-received`, `model-progress`/`download-progress`, `sync-error`.

## Connection flow

1. Host or Join chosen in the connect view.
2. **Host**: pairing codes, LAN signaling server, mDNS registration, QR/passphrase.
3. **Join**: mDNS discovery, or scan QR / paste `#code.token`.
4. WebRTC handshake; `peer-connected` → peer list updates.
5. Sync/analysis progress flows via events.

## Locales

8 languages (`en.json` … `pap.json`); `en` is canonical. Add new keys to all
locales or `scripts/check-translations.js` fails CI and the pre-commit hook.

## Testing

- `npm run test` — vitest: the backend seam (guest + webHost casing tests), stores,
  composables, runtime detection, media.
- `npm run typecheck` — vue-tsc.
- Contract correctness is guaranteed upstream in Rust
  (`generated_ts_matches_catalog`); the frontend drift-guard is the committed file
  itself, regenerated by `cargo build -p siegu-core`.

See [backend.md](backend.md) and [e2e.md](e2e.md) for the transport side and the
end-to-end browser/WebRTC checks.
